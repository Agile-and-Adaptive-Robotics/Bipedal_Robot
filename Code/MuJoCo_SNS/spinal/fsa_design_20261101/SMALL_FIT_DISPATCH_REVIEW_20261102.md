# Small-fit dispatch: prelaunch peer review

Read-only review by Session 1, easteregg2. Reviewed the initial `hunt_trial_adapter.py`, `campaign_budget.py`, `campaign_run.py`, and `virtual_walker_20261031\rustuna_transfer.py` before a new fit. Findings were sent to the campaign owner; this reviewer did not modify the dispatcher. Later fixes need their own confirmation against the final files.

## Fix before using the initial dispatcher

1. **Preserve study provenance during probes.** In the reviewed `rustuna_transfer.py`, `--probe-only` bypasses the existing-trial refusal, then unconditionally rewrites `MANIFEST.json`, `PROVENANCE.json`, and `ADAPTER_SOURCE.py`. It can reset the original start time or replace the scientific lineage of an existing study. A probe of an existing folder must compare and preserve its provenance, or use an explicitly separate folder. A partially started folder with provenance but no completed trial must not silently become a new study either.
2. **Bind the measured baseline to the candidate.** `hunt_trial_adapter.preflight` verifies that the configuration names a selected profile, but checks only finite/complete/knee fields in `baseline_result`. It does not establish that this result was generated by that same configuration/profile. Require normalized configuration identity, consumed source/profile hashes, and the corresponding measured baseline before fitting. A successful old source pilot must not qualify a different integrated FSA condition.
3. **Terminate owned descendants on interruption.** A physical trial runs as a child of the persistent dispatcher. `Worker.close` terminates only the dispatcher if its graceful shutdown fails. Interrupting the outer optimizer while a physical child is active can leave that child running. Register owned child PIDs/process groups and clean up only that owned tree, including keyboard interruption and timeout paths. `campaign_run` likewise needs `finally` cleanup if its wrapper is interrupted. No global simulator kill is appropriate.
4. **Reconcile best-on-resume.** The append-only ledger can contain a completed trial even when a crash prevented the following `BEST.json` write. Resume derives a best row internally but does not immediately reconcile that file; a completed/resumed study can expose an old `BEST.json`. Regenerate it from the verified completed ledger before new work or final reporting. Preserve and classify an interrupted final JSONL line rather than silently discarding evidence.

## Scientific scope that is correct in the reviewed design

- Only two shared E/F timing budgets are sampled; the same values are used for both legs. No independent left/right fit is introduced.
- Body evaluations use fresh Python interpreters. The persistent process is the dispatcher, not the mutable Hunt/runner controller state.
- The new profile changes declared timing conductances. The actual baseline mechanical settings, source force law, limits, rig, and timestep are retained. Disabling graph/diagnostic exports changes recording cost, not controller physics.
- The existing continuous stage-2 mechanical score provides a useful failure gradient, while nonfinite/incomplete and hyperextending trials receive large penalties. Its scalar rank is **not** a completed Hunt expected-afferent fit or a curriculum pass. In particular, a finite frontal failure still has a finite objective; the selected candidate must satisfy actual acceptance and repeat stages1/2 with the same saved parameters before progressing.
- Absolute training/verification stops, per-trial timeout, and a 24-trial cap preserve the intended bounded scope. Include startup, watchdog shutdown, and final artifact writes in wall-time reporting; do not present only the integration kernel as total trial time.

The corresponding baseline capture and saved-state plotting work is independent of this review. No body, neural fitting, optimization, or physics change was launched for the dispatcher review.
